# DaVinci Resolve 接入设计

状态：设计与本机开发文档核查，**尚未连接 Resolve 或修改实际项目**。渲染器能输出独立音效片段，但本仓库尚无可用的 Resolve 自动导入命令。

## 首个可交付目标

对指定片段导入独立音效，保留原视频与口播，按用途放到新音轨，附上可定位的标记。用户能单独移动、替换和静音一条声音。一次执行产生可回退的时间线副本及导入清单。

不把 Fairlight 界面上存在的功能自动当成公开脚本 API。先用可靠的文件预处理和音频导入，逐步验证后再扩展插件、总线与自动化。

## 已核实的 API 与限制

核查依据：本机安装附带的 `Support/Developer/Scripting/README.txt`，文档日期 2025-08-18。它以 Resolve Studio 为说明背景；运行版本、具体版本授权及脚本访问方式仍须现场读取。本机安装记录指向 20.2，当前官网介绍可能是更高版本，不能混用能力结论。

| 文档接口 | 可用于 | 仍要实测 |
|---|---|---|
| `GetProductName / GetVersionString` | 识别实际运行产品和版本 | 当前环境是否允许所选脚本访问方式 |
| `GetCurrentTimeline / GetStartFrame / GetSetting` | 读取目标时间线与时间基准 | 非整数帧率、起始时间码和片段入点 |
| `DuplicateTimeline` | 生成制作副本 | 复制结果和当前时间线是否正确 |
| `ImportMedia` | 导入 WAV | 返回结果、采样率、声道映射 |
| `AddTrack / SetTrackName` | 新建、命名音轨 | stereo 子类型及实际轨号 |
| `AppendToTimeline` 的 `mediaType:2`、`trackIndex`、`recordFrame` | 音频精确放置 | 源 `endFrame` 边界语义、分数帧支持、重叠处理 |
| `AddMarker` 与 `customData` | cue 标识与定位 | 标记帧相对时间线起点的换算 |
| `GetItemListInTrack / GetStart / GetEnd` | 导入后读回验收 | 不同版本浮点或整帧行为 |

文档还提供 `InsertAudioToCurrentTrackAtPlayhead`，但依赖当前轨道与播放头，不作为无人值守默认路径。`TimelineItem.SetProperty("Pan")` 在这份文档中是画面位置，**不是音频声像**。没有依据声称可以通过该属性调整 Fairlight 平移、插件参数、总线或完整音量自动化。

Fairlight 本身有音量、EQ、自动化和人声驱动的音乐避让等功能；这些是产品能力证据，不是脚本可控性的证据。[官方 Fairlight 介绍](https://www.blackmagicdesign.com/products/davinciresolve/fairlight)。

## 导入流程

1. **只读探测**：获取当前项目、时间线名、唯一标识、帧率、起始帧、轨道、选定区间。失败则输出具体缺失能力，不自动改变网络脚本设置。
2. **制定导入计划**：解析渲染清单，验证文件哈希、时长及 `status=render_verified`；计算每条 WAV 的位置、轨道和预计覆盖范围。显示待新增轨道及片段数量。
3. **创建副本**：复制目标时间线，生成此次操作的唯一 run ID。所有新增音轨使用清晰前缀，保护原视频、旁白与已有音轨。
4. **导入素材与片段**：批量导入 WAV，按 role/lane 新建轨道，逐条放置。在允许执行前先做一个 1 帧、2 帧音频的边界小测试，确定 `startFrame/endFrame` 转换。
5. **标记与读回**：记录 cue ID、资产哈希、处理参数摘要；读取每条片段实际起止和轨道，与计划比对。不能以 API 返回非空代替验收。
6. **记录结果**：保存版本、项目/时间线标识、媒体标识、轨道映射、每条片段 ID 及实际坐标。中断时保留报告，恢复执行前先查重。

默认输出独立片段；可附完整等长 SFX 分轨，方便用户快速拖入。不得同时启用片段和同内容分轨，避免重复发声。

## 时间坐标：三个空间不能混淆

渲染器的 `start_sample` 相对输入片段起点；时间线帧可能从非零值开始；音频自身还存在文件起点、剪辑范围和声学峰值。导入时必须同时记录。

假设 `fps = numerator / denominator`，采样率 `SR = 48000`：

```text
target_sample = round(target_frame * SR * denominator / numerator) + offset_samples
start_sample  = target_sample - feature_sample
frame_offset  = floor(start_sample * numerator / (SR * denominator))
record_frame  = segment_start_timeline_frame + frame_offset
```

若接口只能整帧放置，不能简单丢弃剩余采样。计算该帧对应的采样点，在单条 WAV 前补剩余静音；若舍入导致负数，则向前再取一帧。这样峰值仍可位于指定采样点。毫秒不是视频帧，drop-frame 只是时间码显示规则，不能改动真实帧率计算。

`endFrame` 是否包含末帧必须实测。内部范围统一为 `[start, end)`，只有适配器按已验证的版本转换。素材尾音、导入片段长度、源采样数均保留，不能为省事把所有片段切成整数秒。

## 可编辑性与回退

- 渲染器当前把 EQ、声像和避让烘焙进每条 WAV。这是可移动、可替换的独立素材，不等同于完整可编辑的 Fairlight 效果链。
- 音效移到另一句口播下时重新渲染避让；后续如验证原生 automation API，再提供原生处理模式。
- 所有使用同一时段的音效分配到不同 lane，避免同轨覆盖。逻辑 lane 只用于规划，真实音轨号以 API 读回为准。
- 用 run ID、cue ID、渲染哈希和时间线副本做重复执行保护。默认重复请求复用已核验结果；源配置改变则产生明确的修订计划，不静默追加一遍。
- 中途失败只清理或回退本次副本内由本次操作创建的对象。避免使用项目级破坏性撤销，也不删除用户原轨。

## 必须通过的现场用例

| 用例 | 通过条件 |
|---|---|
| 非零时间线起点、任意片段入点 | 片头/中段/末尾各一处实际位置与计划一致 |
| 30、60、24000/1001、30000/1001 | 帧位无累计漂移；显示时间码与采样时钟分开 |
| 两条重叠音效 | 两条均存在且完整，无相互覆盖 |
| 单帧与双帧源范围 | 导入长度正确，确认边界语义 |
| 源文件改动或缺失 | 导入前明确失败，不出现半套无声结果 |
| 重复执行、中途停止后恢复 | 不重复新增已导入的 cue |
| 原轨与图片核查 | 原时间线保持，制作副本内原视频/人声未被修改 |
| 导出后回听与测量 | 卡点、声道、人声、削波、尾音符合要求 |

如果直连脚本不可用，可以输出有共同起点的分轨供手动导入。文档列出的 OTIO/AAF 导入也是候选路径，但增益、淡变、声道和坐标往返保真需另行验证，不能承诺无损保留所有效果。
