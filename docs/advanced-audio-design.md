# 从音效搜索到可编辑的声音设计

日期：2026-10-29。基于上游提交 `11e92dc42726c063007b2fe3fb4ecc3415d1eb20`。

## 结论与边界

优先做「读懂动作 → 安排声音 → 保持人声清楚 → 导出可编辑分轨 → 等响试听」。扩充音效网站排在后面。增加素材数量，不能直接解决卡点、音色统一和人声遮盖。

作者公开 README 只提到“满血版”、BGM skill 和人声优化混音 skill，没有提供详细功能规格。本方案是依据公开代码与实际制作问题提出的独立实现，不声称复刻付费内容，也不把推测写成已知功能。

## 公开版实际做了什么

| 范围 | 已核实行为 | 需要补充 |
|---|---|---|
| 素材搜索 | `scripts/sfx.py` 仅实现 Freesound，抓取网页结果 | README 列举的其他站点不能视为可用适配器 |
| 候选排序 | 下载量、评分、标题、截短描述 | 动作语义、材质、声音包络、同片一致性 |
| 下载 | `fs:` 标识、高质量 MP3 预览 | 记录 preview/original、原格式、哈希及完整来源 |
| 授权 | 可筛 CC0 / BY，默认 `any` | 项目级许可策略、完整署名、未知许可拒绝进入成片 |
| 制作 | 人工/Agent 自行接 FFmpeg | 统一 cue 表、分轨、可重复渲染、试听验收 |
| 达芬奇 | 无集成 | 时间线读回、音轨布局、重复执行保护 |

网页搜索受站点改版影响。下载量只能作为候选线索，不能证明音质、语义适配或观众喜好。

## 已实现：本地分层渲染原型

入口：[`scripts/render_cues.py`](../scripts/render_cues.py)。需要 Python 3.10+、NumPy 和可调用的 FFmpeg；不会自行安装软件或访问外网。

```sh
python scripts/render_cues.py local-cues.json --output renders/take-01
python -m unittest discover -s tests -v
```

配置示例：[`examples/cue-sheet.design.json`](../examples/cue-sheet.design.json)。它是待填素材的模板，未核验来源和哈希时会拒绝执行。资产路径相对于 JSON 文件；本地配置可引用绝对路径。账号、素材、用户音视频不提交到本仓库。

当前行为：

1. 校验素材哈希及本地授权审核标记，按指定范围截取、调整时长、滤波、淡入淡出及声像。
2. 用有理数帧率换算 48 kHz 采样位置。声音可按起点或短时能量峰对齐画面，避免把文件头误当作敲击发生时刻。
3. 按人声能量生成平滑的音效衰减曲线，支持提前量、保持和恢复时间。只降低音效，不改人声增益。它是能量检测，不是语言理解或完善的 VAD。
4. 输出逐条 WAV、音效分轨、人声分轨、完整混音和 `render-report.json`。相互重叠的片段分配到不同逻辑轨道，为剪辑软件导入做准备。
5. 检查采样削波、测量真峰值和响度。超标输出标记为 `failed_true_peak`，命令失败，不能当成可交付成品。失败目录保留诊断，下一次使用新目录。

核心时钟关系：`start_sample + feature_sample = target_sample`。帧编号相对于片段起点；非整帧微调单独写 `target_offset_samples`。不累计浮点秒数来推算长时间线。

本地 40 秒、60 fps 口播片段已跑通 8 个来源、29 条音效层；画面码流保持相同，输出 2400 帧，测得人声延迟 0 个采样，完整解码通过。A/B 完整混音响度差为 0.00 LU，另提供等响的纯音效试听。数字指标不代表听感优劣，主观质量仍由实际试听判断。

4 项测试覆盖非整数帧率、避让曲线、峰值对齐与重叠轨道、分轨还原、源文件变动和重复输出保护。达芬奇实际导入尚未测试。

## 进阶能力如何实现

| 能力 | 具体实现 | 验收方式 | 状态 |
|---|---|---|---|
| 动作级编排 | 优先读动画事件、剪辑时间线和字幕；无结构数据时才分析画面。把进场、接触、停稳分开，并标记置信度 | 声音有明确动作依据；不为每个字、每次变化机械加声 | 本次人工编排已实测；自动规划待做 |
| 材质与音色统一 | 每段限定声音家族；标题、卡片、键鼠分别确定主音与辅助层；控制重复和密度 | 相邻镜头风格连续，重要落点比辅助动作突出 | 当前 cue 参数可表达；自动选材待做 |
| 人声避让 | 基础能量侧链已实现；下一步加入字幕句间隙、辅音敏感频段、事件重要度和更可靠的语音检测 | 口播清晰；避免抽吸感；短句不被过度压低或抬高 | 能量侧链原型已完成 |
| BGM 编排 | 先给出情绪/强度曲线，再选合法曲目；按乐句剪接、保留转折与结尾收束；人声下压低，停顿按语义恢复 | 乐句衔接自然，强拍服务叙事，结尾不任意掐断 | 设计，尚无音乐样片验证 |
| 人声优化 | 先检测噪声、爆音、齿音和动态；只启用必要处理，保留原轨；用等响旁路比较 | 声音仍像本人，无金属伪影，无口型偏移 | 设计；本次仅沿用原模板的增益/保护限幅 |
| 达芬奇可编辑交付 | 每条音效独立导入，添加名称和标记；分轨可静音比较；按导入清单读回核验 | 帧位准确、无覆盖、重跑不重复、原时间线可恢复 | [详细方案](davinci-resolve-integration.md)，未连接验证 |
| 反馈与偏好 | 保存“哪一版、哪段、哪个音效、喜欢/不喜欢的原因”；偏好限定到内容类型与场景 | 能解释后续调整依据，不把一次认可扩展成永久偏好 | 本地记录，不公开用户反馈 |

### 选材与素材管理

先建经过审核的本地素材库，以内容哈希去重。每个资产至少记录标题、作者、来源页面、许可原文入口、下载时间、文件类型、原文件哈希、加工记录和使用场景。短时 RMS、峰值位置、尾音、频谱、单声道兼容性可辅助筛选；不能用这些指标冒充“已经听过”。

候选控制在少量可试听方案中，例如相同动作的轻、中、重三个版本。不要把热门的爆炸或长低频轰鸣当成通用点击声。素材不足时应报告缺口，而非自动用合成音替代所有物件。

Freesound 官方 API 可作为后续适配器：搜索使用 token，原始文件下载涉及 OAuth。原始文件可能本来就是 MP3，并不必然无损。**素材 CC0 与 API 服务的商用许可是两层规则**；接入前核对 API 使用条款。遇到速率限制采用缓存、退避和明确失败，不绕过验证。[API 文档](https://freesound.org/docs/api/)、[鉴权](https://freesound.org/docs/api/authentication.html)、[API 条款](https://freesound.org/docs/api/terms_of_use.html)。

Pixabay 当前公开 API 文档不能据此确认存在音效 API；Mixkit、Kenney 先作为用户已取得合法文件的本地导入源，分别保存对应素材许可，不设计虚构端点。[Pixabay API](https://pixabay.com/api/docs/)、[Mixkit 许可](https://mixkit.co/license/)。

### 混音与公平比较

- 不把每条短音效都归一到统一 LUFS；短瞬态更适合按活跃区 RMS、峰值和上下文调整。
- 完整混音保持人声基准，A/B 只做常量增益匹配，避免把“更响”误认为“更好”。纯音效单听单独匹配，不把单听增益带回正式混音。
- 有人声的示例与无口播的片尾分别处理，不套用一个响度目标。真峰值、声道相位、尾音和截止边界都检查。
- 当前导出的每条 WAV 已包含滤波、声像及避让。移动片段以后，避让不再对应新的人声位置，必须重渲染；原文件和处理参数始终保留。
